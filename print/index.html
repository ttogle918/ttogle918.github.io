해결한 문제

스택도 소유권도 다른 세 도메인 에이전트(금융 · 보험 · 제조)를 잇는 문제. MCP는 자기 도구를 쓰는 층이라, 남의 조직 에이전트에게 일을 맡길 때 필요한 신원 증명 · 사람 승인 대기 · 크로스도메인 추적을 다루지 못한다.

설계 포인트
  • 중립 프로토콜 계층 — 연결 코드를 어느 도메인에도 종속시키지 않고 별도 레포로 분리. Agent Card 3종과 Task JSON Schema 13종을 SSOT로 고정했다.
  • Actor / Subject 신원 분리 — 인증(누가 부르나)과 인가(누구 데이터인가)를 나누고, 위험도별 3단 자격증명 스코프(조회 · 심사 · 자금이동)를 적용했다.
  • HITL 2단 승인 — 자금이동은 요청 부서 → 집행 부서 재무 승인을 거친다. AI는 초안까지만 쓴다. 프롬프트가 아니라 도구 권한 수준에서 강제한다.
  • request_chain_id 분산 트레이스 — MaintQ → FinAllQ → InsuQ 멀티홉 여정 하나를 단일 타임라인으로 묶어 감사 로그에 남긴다.

AI 기반 코드 보안 분석 플랫폼
해결한 문제

LLM 코드 분석에서 발생하는 높은 오탐률과 환각으로 인한 신뢰성 부족. 취약점을 “찾았다”고만 말하는 도구는 실무에서 쓰이지 않는다.

설계 포인트
  • Framework-aware 프롬프트로 초기 40~50%대 오탐률을 대폭 낮췄다.
  • DAST 샌드박스 교차검증 — 취약점을 실제 익스플로잇으로 증명한다. “찾았다”가 아니라 “증명했다”로의 전환.
  • LangGraph 5단계 SAST 파이프라인 — scan → 캐시 분기 → Claude 분석 → 취약점 분류 → 패치 생성. checkpointer로 중단 · 재개를 지원하고, 분석 · 패치 · 증적을 기능 단위 Tool로 나눠 에이전트가 호출한다.
  • 보안 원칙 수호(ADR-016) — 편의성 대신 핵심 보안 원칙을 지키는 쪽을 명시적으로 선택했다.
1인이 팀 규모를 만든 방법
  • Claude Code 멀티 에이전트 오케스트레이션 — main / pm / dev / review / writer 역할을 나눠 병렬로 굴려 1인으로 Sprint 0~30 · 880커밋을 완주했다.
  • 운영까지 붙였다 — Prometheus · Grafana · Jaeger 관측성 스택, SSE(fetch + ReadableStream) + Redis Pub/Sub 실시간 스트리밍, 4중 네트워크 격리, JWT HttpOnly.
  • 클라이언트 확장 — VSCode Extension(인라인 취약점 Diagnostic)과 Android 앱(Kotlin · Compose · FCM)을 같은 백엔드에 붙였다.
성과 — 신뢰성 확보

Spring Boot 4 / Java 21 · FastAPI · LangGraph · Claude API · PostgreSQL + pgvector · Next.js 15를 1인으로 통합해, 실무에 바로 도입할 수 있는 수준의 AI 신뢰성을 확보했다.

키지기 — 개인 개발자용 자격증명 관리 도구 (공개 배포)
해결한 문제

API 키 · 토큰 · ID가 메모장에 흩어진다. 노션의 database_id · data_source_id · page_id는 전부 같은 32자리 UUID라 값만 봐서는 구분이 안 되고, 정규식 기반 시크릿 스캐너는 정확히 이 지점에서 “여러 후보 가능”이라며 손을 든다.

설계 포인트
  • 값이 아니라 맥락으로 분류 — 접두사가 분명한 키(sk- · ghp_ · AKIA)는 정규식으로 즉시 판별하고, 애매한 키는 OCR로 읽은 주변 라벨과 URL 구조로 가린다. 신호가 충돌하면 단정하지 않고 “확인 필요”로 남긴다.
  • 로컬 우선(local-first) — 내가 운영하는 서버가 없다. 마스터 비밀번호에서 Argon2id로 유도한 키로 AES-256-GCM 암호화해 SQLite에 암호문만 저장하고, 외부로 나가는 기능은 전부 사용자가 직접 켜야 하는 옵트인이다.
  • 삭제까지 책임진다 — SQLite 기본 DELETE는 VACUUM 전까지 디스크에 포렌식 복구가 가능하게 남는다. PRAGMA secure_delete + VACUUM으로 그 잔여까지 지운다.
  • YAML 한 장으로 서비스 확장 — 키 종류 · 라벨 · URL 패턴 · 환경변수명 · 검증 엔드포인트를 YAML로 선언하면 파일 하나 추가로 백엔드 · 프론트 양쪽에 자동 반영된다(현재 10종).

2026 오픈소스 개발자대회 출품(결과 대기). v0.5.1을 MIT 라이선스로 공개하고, 홈페이지에서 exe를 내려받아 바로 쓸 수 있게 했다. 설계와 구현뿐 아니라 라이선스 · 보안 고지 · SBOM · 배포까지 혼자 끝냈다.

에이전트 자율 조달 — 역경매 + 조건부 정산
문제 정의

x402는 에이전트 결제의 사실상 표준이 됐지만 일방적이다. 판매자가 가격을 정하고 구매자는 내거나 만다 — 협상도, 경쟁 입찰도, 결제 후 결과가 나빴을 때 되돌릴 방법도 없다.

설계 포인트
  • 역경매 — 하나의 필요를 브로드캐스트하면 판매자 에이전트들이 각자 HTTP 402로 응찰하고, 정책 엔진이 낙찰한다.
  • 조건부 정산(에스크로) — 결제금을 온체인에 잠그고 인도물 검증을 통과해야 release, 실패하면 자동 환불하고 차순위로 재낙찰한다.
  • 판단은 LLM, 강제는 체인 — 지출 한도를 프롬프트가 아니라 온체인 계정에 둔다. 모델이 환각해도 한도를 넘는 트랜잭션은 체인이 거부한다.

설계 결정 19건(D1~D19)과 trace UI 프로토타입까지 만들었고, 온체인 프로그램과 에이전트 루프는 착수 단계에서 멈춰 있다 — 2026.08 시점 상태다. devnet 전용.
