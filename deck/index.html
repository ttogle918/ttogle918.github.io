    통합 대시보드. 상단 규제 경고는 포트폴리오 비율을 계산해 기준값과 비교한 결과입니다.

    여신 심사 근거. 한도 · LTV · 규칙 판정

    문제

    은행·증권을 한 화면에서 다루는 금융 비서는 이상거래 판정이나 이체 차단처럼 나중에 이유를 설명해야 하는 결정을 내립니다. 감사 기록에 «AI가 그렇게 판단했습니다»라고 적을 수는 없습니다.

    주요 기능

    1. 통합 대시보드은행과 증권을 합산하고, 규제 경고는 비율을 계산해 띄웁니다.
    2. 여신 심사 근거 카드심사 때와 같은 판정 로직을 재사용해 화면과 심사가 갈라지지 않습니다.
    3. 여신 ↔ 이체 연결서버가 «출금 가능»으로 판정할 때만 버튼이 나오고, 계좌는 사람이 입력합니다.
    4. 기업 이체 결재 (직무 분리)신청한 사람에게는 취소 버튼만 있고 승인 버튼이 없습니다.
    5. FDS 고위험 → 2FA 승격결재가 끝나도 이상거래 탐지가 다시 평가해 추가 인증(TOTP)을 요구합니다.
    6. 스미싱 탐지키워드 목록 대신 모델로 판정하고, 위험 단어를 근거로 보여 줍니다.
    7. AI 비서범위 밖 질문은 지어내지 않고, 결과를 못 받은 기능은 배너로 알립니다.
    모델IsolationForest (이상거래) · TF-IDF + LogisticRegression (스미싱). 생성형 AI 호출은 0건입니다(전수 검색).

    ★ 01-1 FinAllQ · 무엇을 만들었나
    01-1

    FinAllQ · 설계에서 내린 결정

    LLM을 쓰지 않은 이유

    측정 기준일 2026-09-08
    감사가능성IsolationForest안전장치
    이 서비스가 하는 일은 결국 «어떤 도구를 어떤 순서로 부를까»입니다
    결정 공간

    선택지가 닫혀 있었습니다

    도구는 20종으로 정해져 있고 하는 일도 고정돼 있습니다. 닫힌 문제에 LLM을 넣으면 같은 질문에 같은 답이 보장되지 않고, 왜 그 도구를 골랐는지 설명할 수 없습니다. 그래서 질의와 도구의 키워드를 맞춰 점수가 높은 순으로 최대 3개를 고르게 했습니다.

    감사

    금융은 근거를 남겨야 합니다

    규칙은 어떤 입력이 어떤 규칙을 탔는지가 코드에 그대로 남아, 판정 근거를 감사 기록으로 옮길 수 있습니다. 답변에 실릴 수 있는 항목도 목록으로 정해 두었습니다.

    모델

    규칙이 안 되는 곳에만 모델을 썼습니다

    • 이상거래는 IsolationForest - 정상 패턴의 경계를 사람이 기준값으로 정할 수 없기 때문.
    • 스미싱은 TF-IDF + LogisticRegression - 문구 변형이 끝이 없어 키워드 목록은 바로 뚫리기 때문.
    QMesh에서의 역할 - 공장이 보내는 출금 · 대출 · 정산 요청을 받는 은행입니다. AI가 «승인»이라고 답해도 대출 상태는 «심사 중»으로 남고, 사람이 따로 승인합니다.

    LLM 대신 공들인 안전장치 4가지

    안전장치 하는 일
    ① 권한별 도구 노출 권한 밖 도구는 도구를 고르는 단계에 아예 올라가지 않습니다.
    ② 부작용 도구 자동 실행 금지 «송금해줘»라고 해도 시스템이 알아서 돈을 움직이지 않게, 부작용이 있는 도구는 자동 선택에서 뺐습니다.
    ③ 송금 흐름 FDS 필수 통과 송금 계열 흐름은 이상거래 점수를 건너뛸 수 없게 했습니다. (지금은 발동하지 않습니다. 아래 한계 참고)
    ④ 출력 항목 목록 도구가 무엇을 돌려주든 목록에 등록된 항목만 답변에 실어, 민감정보가 새는 길을 막았습니다.
    LLM으로 바꿀 기준도 미리 정했습니다. 도구 매칭 실패가 눈에 띄게 늘거나 도구가 20종을 크게 넘어 키워드가 자주 부딪치면, 도구를 고르는 부분만 바꿉니다. 그때도 안전장치 4가지는 그대로 둡니다.

    한계 - 아직 안 된 것도 같이 적습니다

    FDS 필수 통과는 자리만대상 도구 목록이 비어 있어 지금은 발동하지 않습니다. 코드 주석과 백로그에 적어 두었습니다.
    재학습 파이프라인 없음학습 데이터가 코드에 고정돼 있습니다. 사용자마다 달라지는 것은 기준선(30일 평균 이체액 등)뿐입니다.
    동의어 · 오타에 약함도구를 키워드 부분 일치로 고르기 때문입니다. 코드 맨 위 주석에 «LLM이 아니다»라고 적어 두었습니다.

    KeyLens

    개인 개발자용 자격증명 관리 도구 (키지기)

    LocalFirstAES-256-GCMOCR분류OpenSource
    문제

    보조강사로 일하며 수강생들이 API 키를 코드에 그대로 두는 걸 자주 봤습니다. 막힌 곳은 노션의 여러 ID처럼 모양이 똑같은 값이었습니다. 값만 봐서는 무슨 키인지 알 수 없었습니다.

    해결
    • 앞부분으로 알 수 있는 키(sk- · ghp_ · AKIA)는 바로 판별하고, 애매한 값은 화면 캡처를 OCR로 읽어 옆 이름표와 주소 구조로 구분합니다. 단서가 엇갈리면 «확인 필요»로 남깁니다.
    • 서버 없이 내 컴퓨터에만 저장합니다(Argon2id + AES-256-GCM). SQLite에서 지운 데이터도 덮어쓰도록 설정했습니다.
    • YAML 파일 하나로 새 서비스를 추가합니다(현재 10종).

    2026 오픈소스 개발자대회 출품. v0.5.1을 MIT 라이선스로 공개했습니다.

    SpendQ

    AI 에이전트가 알아서 구매 · 역경매 + 조건부 결제

    x402A2ASolanaEscrowGemini
    문제

    x402는 AI 에이전트가 돈을 내는 사실상의 표준이지만, 파는 쪽이 값을 정하면 사는 쪽은 내거나 말거나 둘 중 하나입니다. 흥정도, 판매자 간 경쟁도, 결과가 나쁠 때 돌려받을 방법도 없습니다.

    해결
    • 역경매: 판매자 AI들이 가격과 납기를 적어 응찰하고(HTTP 402), 정한 규칙으로 낙찰자를 고릅니다.
    • 에스크로: 돈을 블록체인 금고에 맡겨 두고, 검사를 통과해야 지급하고 실패하면 환불합니다.
    • 지출 한도는 AI 지시문에 두지 않고 블록체인 계정에 걸었습니다. 앱을 건너뛰고 직접 보낸 한도 초과 거래도 체인이 거절했습니다.

    기본 검사만으로는 불량 18건 중 15건, Gemini가 고른 검사를 더하니 18건을 모두 잡았습니다.

    AI 하네스 엔지니어링

    8개 프로젝트에 같은 규칙으로 적용한 AI 작업 관리 틀

    HarnessSubAgentHooksHumanInTheLoop
    문제

    코딩 AI가 계획에 없던 기능을 끌어오고, 테스트가 실패하면 코드 대신 정답 파일을 고쳐 통과시키고, 검토만 맡긴 AI가 코드를 직접 고쳤습니다.

    해결
    • 막는 방법을 지시문(skill) · 도구 권한(setting) · 코드(hook) 세 단계로 나누고, 위험이 큰 프로젝트일수록 더 강하게 막았습니다.
    • 검토 담당 AI에게는 읽기 도구만 줘서 고칠 방법이 없게 했습니다. 채점용 정답 파일 쓰기는 hook이 막습니다.
    • 구현 · 테스트 · 검토 · 커밋은 자동으로 흘러가고, 마지막에 사람 체크리스트에서 멈춥니다.

    hook이 지금도 작동하는지 돌려 보니 3개 중 2개가 한 번도 실행된 적이 없었습니다. || exit 0이 오류를 가리고 있어서 고친 뒤, 위반 사례를 넣어 잡아내는지 확인했습니다.
