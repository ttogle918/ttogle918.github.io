◆ 문제

보조강사로 일하며 수강생들이 API 키를 코드에 그대로 두는 걸 자주 봤고, 시중 도구보다 단순하게 키를 보관할 방법이 필요하다고 생각했습니다. 막힌 곳은 노션의 여러 ID처럼 모양이 똑같은 값이었습니다. 값만 봐서는 무슨 키인지 알 수 없었습니다.

◆ 해결 방법
  • 값이 아니라 주변 맥락으로 분류: 앞부분만 봐도 알 수 있는 키(sk-·ghp_·AKIA)는 바로 판별하고, 애매한 값은 화면 캡처에서 글자를 읽어(OCR) 옆에 적힌 이름표와 주소 구조로 구분합니다. 단서가 서로 엇갈리면 단정하지 않고 «확인 필요»로 남깁니다.
  • 내 컴퓨터에만 저장(local-first): 따로 운영하는 서버가 없습니다. 마스터 비밀번호로 만든 키로 강하게 암호화(Argon2id + AES-256-GCM)해 암호화된 값만 저장하고, 밖으로 무언가 내보내는 기능은 사용자가 직접 켜야만 동작합니다.
  • SQLite는 기본 설정에서 지운 데이터가 디스크에 남아 복구될 수 있어서, 지운 자리를 덮어쓰도록 설정을 바꿨습니다.
  • 설정 파일 하나로 새 서비스 추가: 키 종류·이름표·주소 패턴·환경변수 이름·검증 주소를 YAML 파일 하나에 적어 추가하면, 서버와 화면에 자동으로 반영됩니다(현재 10종).
