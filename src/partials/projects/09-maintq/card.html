◆ 문제

공장 설비(인버터·PLC)에 에러가 뜨면 정비사가 PDF 매뉴얼을 10~30분씩 뒤지고, 부품은 전화와 엑셀로 주문합니다. 기존 설비관리 시스템(CMMS)은 이력·재고·주문을 기록만 할 뿐, «왜 에러가 났고 어떤 부품이 필요한지»는 판단하지 못합니다. 새 기종이 들어오면 매뉴얼은 영문 PDF 한 권뿐이라 더 막막합니다.

◆ 해결 방법 - 위험한 실패부터 줄인다

두 모델의 부품 특정 정확도가 45.6%와 51.0%로 비슷해서 차이가 없다고 넘길 뻔했습니다. 안을 열어 보니 한쪽은 틀린 부품을 자신 있게 골랐고, 다른 쪽은 답을 내지 않았습니다. 틀린 부품을 확신하면 잘못된 발주로 이어지니, 두 실수를 따로 세기로 했습니다. 지시문만 바꾼 비교 실험(각 120회)에서 위험한 쪽을 16.7%에서 1.1%로 줄였습니다.

◆ NVIDIA 해커톤 - 에이전트는 초안까지, 결정은 사람

NVIDIA 해커톤에서 예선을 통과해 상위 10팀에 들었습니다. 미션은 «NemoClaw와 OpenShell로 에이전트 보안하기»였습니다. 영문 매뉴얼뿐인 새 기종(Yaskawa HV600)을 한국어로 진단할 수 있게 하되, AI 번역을 그대로 믿으면 생기는 두 사고(틀린 진단, 틀린 안전 수치)를 막는 데 집중했습니다. 추출은 LLM 없이 코드가, 한국어 초안은 샌드박스 안의 NeMo Agent Toolkit 에이전트(Nemotron)가 스테이징 테이블에만 쓰고, 확정과 안전 문구 승인은 사람이 합니다. 승인 전에는 같은 질문(«HV600에서 GF 떴어»)에 비슷한 코드를 추측하지 않고 A/S로 안내하고, 승인 뒤에는 정의·원인·조치와 사람이 승인한 안전 문구(원문 p.29, 최소 5분)가 나옵니다.

◆ 주요 기능 - 누르면 실제 화면이 열립니다

◆ 아직 안 된 것
  • Nemotron 기준 평가는 다시 재지 않았습니다. 위 수치는 이전 모델(gemini·gpt-oss) 기준이고 이후 지시문이 바뀌어 서로 비교할 수 없습니다.
  • 공개 배포판에는 샌드박스가 없습니다. OpenShell·NemoClaw·NAT는 로컬 게이트웨이를 전제로 해서 배포판에서 뺐고, 녹화 영상으로 보여 드립니다.
  • 승격을 되돌리는 API가 없고, OpenClaw 경로는 안전 문구를 붙이는 게이트 계층 없이 모델이 스킬 규칙을 지키는 데 기댑니다.
  • 실사용자가 없습니다. 재고·공급사·발주는 목업이고 매뉴얼만 실데이터입니다. 특정 공장이 HV600을 쓴다고 주장하지 않습니다.
◆ QMesh에서 맡은 역할

QMesh로 연결하면 MaintQ는 은행(FinAllQ)과 보험사(InsuQ)에 요청을 보내기만 합니다. 설비 보전은 일이 시작되는 자리이지 받는 자리가 아니라서, 받는 쪽은 나중에 할 일이 아니라 하지 않기로 한 일입니다. 보내는 요청 6경로는 종단 검증했고, 샌드박스 안에서는 시연하지 않았습니다. QMesh 카드에서 연결 전체를 볼 수 있습니다.
