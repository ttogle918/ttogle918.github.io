QMesh 연결 에이전트 · 제조

틀린 부품을 확신하는 실수부터 줄였다

공장 설비(인버터·PLC)에 에러가 뜨면 정비사는 PDF 매뉴얼을 10~30분씩 뒤지고, 부품은 전화와 엑셀로 주문합니다. 기존 설비관리 시스템(CMMS)은 이력·재고·주문을 기록할 뿐, 왜 에러가 났고 어떤 부품이 필요한지는 판단하지 못합니다. MaintQ는 에러를 진단하고 재고·견적을 확인해 발주서 초안까지 만드는 AI 에이전트입니다. 승인과 서명은 사람만 합니다.

주요 기능

모르면 모른다고, 모자라면 판정하지 않는다

아래 화면은 시드 데이터 그대로, 실제 API 응답으로 찍은 캡처입니다. 데이터는 공개 매뉴얼과 생성한 시드이고, 실사용자는 없습니다.

설계에서 내린 결정

합계가 지워 버리는 위험한 실패를 따로 센다

두 모델의 부품 특정 정확도가 45.6%와 51.0%로 비슷해서 차이가 없다고 넘길 뻔했습니다. 안을 열어 보니 한쪽은 틀린 부품을 자신 있게 골랐고(오특정), 다른 쪽은 답을 내지 않았습니다(미특정). 현장에서 오특정은 엉뚱한 발주로 이어지고, 미특정은 답을 못 받는 것일 뿐입니다. 같은 실패로 합치면 더 위험한 쪽이 더 좋아 보입니다.

도구 경계

조회와 검색을 다른 도구로

도구 22종(기본 7 + 확장 15) 각각에 «언제 쓰고 언제 쓰면 안 되는지»를 적었습니다. 정확히 맞아야 하는 에러코드 조회는 검색이 아닌 조회 도구로 따로 두었고, 실패도 오류가 아니라 정해진 상태값으로 돌려줘 에이전트가 다음 행동을 고를 수 있게 했습니다.

쓰기

AI는 초안만, 신원은 서버가

쓰기 도구는 3종뿐이고 셋 다 초안만 만듭니다. 고칠 권한 자체가 없어 승인 · 반려 · 서명은 사람 전용 화면에서만 일어납니다. 요청한 사람의 신원도 도구에 넘기는 값이 아니라 서버가 넣어서, AI가 신원을 꾸며 낼 길이 없습니다.

측정

몇 번 돌려야 믿을 수 있는지부터

정답률이 50% 안팎인 문항은 20번을 돌려도 95% 신뢰구간 폭이 40%p였고, 같은 조건의 10번짜리 묶음 둘이 인용률에서 12%p 어긋나기도 했습니다. 10번 돌린 수치를 그대로 인용하면 있지도 않은 성능 저하를 보고하게 됩니다. 그래서 위 비교는 각 120세션으로 돌렸습니다.

회귀 검사 1,560건은 단독 실행 계약 스크립트 34종의 단언 1,212건과 pytest 22파일 348건을 합친 수입니다(2026-09-11 기준). 설계 결정은 D1부터 D141까지 한 문서에 빠짐없이 적었습니다.

한계

아직 안 된 것도 같이 적습니다

아래 첫 두 항목은 gemini-2.5-flash로 20문항 × 3회차를 돌린 측정(2026-08-17)입니다. 위 통제 비교와는 모델이 달라 두 숫자를 개선 폭으로 비교할 수 없습니다.

목표 미달

부품 특정은 목표 90%에 못 미친다

gemini-2.5-flash 측정(2026-08-17)에서 부품 특정 정확률은 40.0%(18/45)로 목표 90%에 크게 못 미쳤습니다. 모델이 다른 측정끼리는 비교할 수 없어, 이후 기준선과 나란히 놓지 않았습니다.

목표 미달

근거 인용과 안전 경고도 미달

근거 페이지 인용률은 90.7%(49/54)로 목표 100%에, 안전 경고 통과는 70.4%(38/54)로 목표(누락 0건)에 못 미쳤습니다. 안전 경고 쪽은 매뉴얼을 조회하지 않은 턴에서 근거 없는 안전 문구를 막은 결과라, 고칠 곳은 매뉴얼을 건너뛰는 패턴입니다.

목업

현장 효과는 재지 못했다

데이터는 공개 매뉴얼과 생성한 시드이고 실사용자가 없어, «고장에서 발주까지 30분 이상 → 5분»은 가설 지표로만 적어 두었고 실제로 재지 못했습니다.

QMesh에서 맡은 역할

일이 시작되는 공장, 요청을 보내는 쪽

QMesh로 연결하면 MaintQ는 은행(FinAllQ)과 보험사(InsuQ)에 요청을 보냅니다. 받는 요청은 설계상 없습니다. 설비 보전은 일이 시작되는 자리이지 받는 자리가 아니라서, 나중에 할 일이 아니라 하지 않기로 한 일입니다. 외부 호출 도구도 상대의 자격증명을 직접 쓰지 않고 백엔드를 거쳐 보냅니다.

보내는 요청 받는 쪽 하는 일 상태
lookup-clause InsuQ 설비 손해가 약관상 보장되는지 근거 조항 조회 종단 검증
request-withdrawal (S5) FinAllQ 팀장 · 재무팀 승인 뒤 부품 대금 출금 요청 종단 검증 (결재함 도착까지)
assess-loan (S8) FinAllQ → InsuQ 설비 담보 대출 심사 - 은행이 보험사에 담보 보험 확인 종단 검증
assess-used-equipment-loan (S13) FinAllQ → InsuQ 중고 설비 담보 대출 심사 - 심사 결과일 뿐 대출 실행은 아님 종단 검증
request-settlement (S12) FinAllQ 매각대금 정산 - 응답으로 처분 제한이 풀려도 결정 문서는 초안 종단 검증
notify-asset-change (S11) InsuQ 설비 처분 통지 - 같은 키로 다른 내용이 오면 거절 종단 검증
advise-policy-renewal (S7) InsuQ 고장 이력을 반영한 화재보험 갱신 조건 제안 InsuQ 쪽만 준비, MaintQ 미연결
notify-risk-change (S14) InsuQ 새 설비 도입에 따른 위험등급 변동 통지 보류 - 계약이 위험도를 숫자로 요구
advise-hedge (S6) · advise-financing (S16) FinAllQ 환헤지 · 설비 구입 자금 조달 상담 만들지 않음 - 통화 데이터와 시작할 계기가 없음
